# DataHub 数据源配置说明

系统配置 → 数据源配置是统一的数据源管理入口。供应商的中文说明、能力清单、费用、鉴权方式和风险提示由后端注册表维护，页面只保存运行时启停状态、非敏感参数和加密凭证。

## 配置步骤

1. 进入“系统配置 → 数据源配置”，先阅读每张数据源卡片的能力和风险说明。
2. 需要 Token 的来源（Tushare Pro、开盘啦原生）在 Token 输入框录入合法凭证。保存或测试完成后输入框会立即清空，页面只显示末四位提示。
3. 点击“测试连接”。测试按能力执行，结果会显示有效行数、延迟、数据时间和中文错误原因。Tushare 的基础 Token 可用不代表每项开盘啦能力都有积分，需逐项测试。
4. 测试通过后再启用来源。开盘啦原生接口默认停用；没有管理员提供的合法 Token 时不会影响免费行情。
5. 在“能力路由”中选择自动或固定模式。自动模式按来源顺序降级；固定模式只使用指定来源，失败时返回明确错误。

配置更新带版本号。若两个管理员同时编辑，后提交者会收到 409，刷新页面后再保存。探测结果绑定供应商、能力、凭证指纹和契约版本，15 分钟后或凭证变化后必须重新测试。

## 命令行真实测试（按需）

普通测试不会访问公网。管理员在已配置数据库和凭证的环境中，可显式执行一项能力测试：

```bash
cd backend
.venv/bin/python -m app.cli.datahub --provider tushare --capability kpl.limit_list
```

命令只输出中文安全摘要，不输出 Token 或供应商原始异常。未配置付费凭证会返回“未配置”并正常结束；鉴权、权限、网络或字段契约失败会以非零退出码提示。

## 数据状态

- `fresh`：在能力时效窗口内取得的新数据。
- `stale`：上游暂时失败时返回的最近有效数据，页面会显示来源和数据时间。
- `503`：没有任何有效或最近有效数据，页面显示可重试提示，绝不会用 `0.00` 伪装行情。

凭证不会写入数据库明文、API 响应、浏览器 DOM、构建产物或日志。Redis 只用于缓存、失效提示、限流和熔断；Redis 暂时不可用时，平台会回查 PostgreSQL，并使用进程级短 TTL 和保守限流继续保护上游。
