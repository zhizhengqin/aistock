# DataHub 数据源配置说明

系统配置 → 数据源配置是统一的数据源管理入口。供应商的中文说明、能力清单、费用、鉴权方式和风险提示由后端注册表维护，页面只保存运行时启停状态、非敏感参数和加密凭证。

## 配置步骤

1. 进入“系统配置 → 数据源配置”，先阅读每张数据源卡片的能力和风险说明。
2. 需要凭证的来源按卡片上的字段元数据填写。Tushare Pro 的 Token 必须来自 Tushare Pro 控制台，只用于 Tushare 的 `kpl_*` 数据集，不是开盘啦原生 Token；开盘啦原生必须同时填写开盘啦合法 `UserID` 和 `Token`，不能填 Tushare Token。保存或测试完成后输入框会立即清空，页面不会回显 secret。
3. 点击某张卡片的“测试连接”。测试按能力执行，结果只显示在对应卡片的按钮下方，包含有效行数、延迟、数据时间和中文错误原因；页面顶部只显示初始加载或刷新失败。Tushare 的基础 Token 可用不代表每项既有能力都有权限，需逐项测试。
4. 测试通过后再启用来源。开盘啦原生接口默认停用；没有管理员提供的合法 `UserID + Token` 时不会影响免费行情。
5. 在“能力路由”中选择自动或固定模式。自动模式按来源顺序降级；固定模式只使用指定来源，失败时返回明确错误。

配置更新带版本号。若两个管理员同时编辑，后提交者会收到 409，刷新页面后再保存。探测结果绑定供应商、能力、凭证指纹和契约版本，15 分钟后或凭证变化后必须重新测试。

## 能力边界与分析取数规则

- Tushare Pro 保留既有六项盘后/分析能力；这些能力不代表开盘啦原生接口已经可用。
- 开盘啦原生只声明已确认的四类动作：个股题材标签（`kpl_native.stock_tags`）、板块排行（`kpl_native.plate_ranking`）、板块成分（`kpl_native.plate_constituents`）和股票排行（`kpl_native.stock_ranking`）。涨停梯队、强势板块和竞价开盘等未完成协议验证的动作不会伪装成可用能力，卡片会标注“实验性、需账号实测”。
- 股票分析先使用实时快照中的 PE(TTM)、PB 和总市值；财务摘要只补快照缺失字段。公司名称和行业来自独立的 `stock.profile` 资料能力，资料缺失时页面显示 `N/A`。
- 资金流允许字段缺失，质量信息会列出 `missing_fields`。东方财富不可用时，新浪只补充真实可解析的日资金流字段，无法解析的字段保持缺失，不会填 0。

## 开盘啦真实账号验收

协议夹具测试不等同于真实账号验收。只有在运行环境同时提供 `KPL_USER_ID` 和 `KPL_TOKEN` 时，live-smoke 才会尝试四类已声明原生动作；任一变量缺失时测试会明确跳过并记录“未完成真实账号验证”。账号、Token 和接口原始响应不得写入仓库、日志、截图或文档。

## 命令行真实测试（按需）

普通测试不会访问公网。管理员在已配置数据库和凭证的环境中，可显式执行一项能力测试：

```bash
cd backend
.venv/bin/python -m app.cli.datahub --provider tushare --capability kpl.limit_list
```

命令只输出中文安全摘要，不输出 Token 或供应商原始异常。未配置付费凭证会返回“未配置”并正常结束；鉴权、权限、网络或字段契约失败会以非零退出码提示。

## 数据状态

- `fresh`：在能力时效窗口内取得的新数据。
- `stale`：上游暂时失败时返回的最近有效数据，页面会显示来源和数据时间。
- `503`：没有任何有效或最近有效数据，页面显示可重试提示，绝不会用 `0.00` 伪装行情。

凭证不会写入数据库明文、API 响应、浏览器 DOM、构建产物或日志。Redis 只用于缓存、失效提示、限流和熔断；Redis 暂时不可用时，平台会回查 PostgreSQL，并使用进程级短 TTL 和保守限流继续保护上游。
